# BigBang 编辑模式分析与开发计划

## 1. 文档目的

本文基于 Smartisan BigBang 3.2.0 APK 的 JADX 反编译源码、原版实机截图，以及 Nova Text 当前代码，回答四个问题：

1. 原版“编辑模式”在界面上是什么样；
2. 用户可以完成哪些操作，操作之间如何切换；
3. 原版内部如何组织编辑、选区、光标和历史；
4. Nova Text 应如何在保留现有 legacy 词块内核的前提下补齐这项能力。

本文是编辑模式专项规格与实施计划。项目总体进度仍以 [development-plan.md](./development-plan.md) 为准，已存在的组件职责仍以 [architecture.md](./architecture.md) 为准。

## 3. 原版编辑模式的产品形态

### 3.1 它不是普通文本框

原版没有把全文切换成一个全屏 `EditText`。进入编辑模式后，文本仍以 BigBang 词块形式展示，但词块从“分词结果”转成更细的可编辑单元，并增加一个悬浮的大光标工具。

这使编辑模式同时保留两套能力：

- BigBang 的词块点击、滑动多选、选区背景和随动工具条；
- 文本编辑器的插入点、删除、空格、换行、粘贴、软键盘、撤销和重做。

因此，编辑模式本质上是“词块原地编辑器”，不是独立页面，也不是把现有词块 UI 替换为 Compose 文本框。

### 3.2 未选择状态 UI

由截图与资源可以确认：

- 顶栏左侧：
  - 返回箭头：退出编辑模式，回到普通 BigBang 状态；
  - 关闭按钮：关闭整个 BigBang 页面；
- 顶栏中间：标题“大爆炸”；
- 顶栏右侧：
  - 全选 / 取消全选；
  - 分享；
- 内容区右上角：显示总字数，例如“共 84 字”；
- 文本词块：中文在截图中按单字拆开，标点和空白也保留独立位置；
- 插入位置：词块之间显示细竖线；
- 大光标工具：位于当前插入点附近，由一条连接线与插入位置相连；
- 大光标从左到右包含：
  - 空格；
  - 标点 / 符号面板；
  - 中央拖拽把手；
  - 删除；
  - 回车；
  - 下方语音输入按钮；
- 底栏：撤销、重做、呼出系统键盘。

原版资源给出的关键尺寸是：普通词块行高 `54dp`，编辑态词块行高 `40dp`，编辑词块最小宽度 `24dp`，顶/底编辑栏高度 `48dp`。这些数值可作为视觉基线，但 Nova Text 仍需经过不同密度、字体缩放和横屏验证，不能直接假定像素级照搬即可正确。

### 3.3 选择状态 UI

选择一段词块后：

- 被选词块使用蓝色底、白色字；
- 多选区域出现浅色整体选区背景；
- 大光标仍保留在插入位置，便于取消选择后继续编辑；
- 选区上方出现编辑专用操作条；
- 截图中的操作从左到右为：
  - 删除；
  - 语音替换；
  - 语音输入；
  - 取消选择；
  - 剪切；
  - 复制；
  - 粘贴；
- 普通模式下的搜索、词典、联系人、分享等选词动作在编辑态被替换，避免把“编辑动作”和“查询动作”混在同一工具条。

`SelectToolbar.setButtonsVisibility(...)` 进一步确认：编辑态显示删除、剪切、复制、粘贴和语音动作；隐藏搜索、词典、分享和 URL 跳转。复制始终可用，粘贴用于替换当前选区。

## 4. 原版功能与交互细节

### 4.1 进入编辑模式

普通 BigBang 顶栏的书写图标触发 `onEditClick(true)`。原版随后：

1. 锁定动作状态，避免转场期间重复点击；
2. 将当前完整文本转换为编辑态细粒度词块；
3. 从普通居中布局切换为顶部对齐；
4. 将普通背景、行高和词块背景切换为编辑样式；
5. 初始化大光标，并延迟显示以等待词块重排结束；
6. 顶栏切换为“退出编辑 + 关闭 + 分享 + 全选”；
7. 底栏切换为“撤销 + 重做 + 键盘”；
8. 前三次进入时提示“拖动大光标到任意位置，可添加文字”。

原版还支持通过 Intent 的 `enter_edit_mode` 直接进入编辑态，但 Nova Text 首轮无需增加新的外部入口；应先把页面内入口做稳。

### 4.2 插入点与大光标

- 点击词块：把插入点移动到该词块之后；点击换行词块时使用换行前的正确边界。
- 点击词块边缘或空白边界：把插入点移动到最近的合法位置。
- 长按中央把手约 `150ms` 后开始拖拽，可把插入点移动到任意词块间隙。
- 拖动时光标、连接线、内容自动滚动和工具条需要同步更新。
- 拖动结束后若剪贴板有文本，可在光标附近显示粘贴入口。
- 插入点必须位于编辑单元边界，不能落入 UTF-16 代理对、组合字符或 emoji 序列中间。

### 4.3 大光标动作

- 空格：在插入点插入空格；原版带连续点击判定和视觉反馈。
- 符号：打开标点面板，选择后在插入点插入符号。
- 删除：删除插入点前一个编辑单元；长按后约每 `50ms` 连续删除，快速连点也有连续状态判断。
- 回车：插入换行，并触发重新排版。
- 语音：按住说话，识别文本插入当前光标位置；短按会提示需要长按。
- 系统键盘：底栏键盘按钮让一个隐藏输入控件取得焦点，输入内容被转换为词块更新；这不是用键盘直接编辑一个普通全文文本框。

Nova Text 首轮核心验收包含空格、删除、回车、粘贴和系统键盘；原版语音依赖 Smartisan 在线服务，单列后续兼容，不作为核心编辑模式的完成门槛。

### 4.4 选区动作

- 点击或滑动词块形成选区，继续滑动扩展或收缩选区。
- 取消：只清空选择，不退出编辑模式。
- 删除：删除所选编辑单元，并把插入点落在原选区起点。
- 剪切：先写入系统剪贴板，再删除选区，并显示“已剪切到剪贴板”。
- 复制：写入系统剪贴板，不修改文本。
- 粘贴：用剪贴板文本替换选区；剪贴板为空时提示无可粘贴内容。
- 全选：在“全选”和“取消全选”之间切换。
- 语音替换：识别结果替换选区；语音输入则在当前编辑位置插入。

原版的选择集合由有序词块 ID 维护，工具条和选区背景随顶行、底行及滚动位置重算。Nova Text 已有这部分普通模式能力，应扩展其动作集合，不应新建第二套选区控件。

### 4.5 撤销、重做和脏状态

- 每次插入、删除、剪切、粘贴、替换、换行和空格操作都进入编辑历史。
- 撤销与重做按钮只在相应历史栈可用时启用。
- 新编辑发生后清空重做分支。
- 退出编辑模式会提交当前编辑文本到本次 BigBang 会话，并以该文本重新分词。
- 关闭整个页面时，如果编辑历史表明文本已修改，原版提示“要舍弃你所做的更改吗？”。
- 原版通过 `onSaveInstanceState` 保存编辑状态；旋转后仍处于编辑态，内容、选择、光标与历史不能静默丢失。

### 4.6 返回与关闭不是同一动作

原版明确区分：

- 顶栏返回箭头：退出编辑态，但保留已编辑文本，重新进入普通 BigBang；
- 顶栏关闭按钮 / 系统返回：准备关闭页面，若有未提交更改则确认是否舍弃；
- 对可回写的 Smartisan 便签等资源，原版还可保存回来源；
- 对普通来源，分享使用编辑后的全文或当前选区。

Nova Text 无权修改 OCR 或无障碍捕获来源的第三方界面，所以不得把“保存”描述成跨应用回写。Nova Text 的提交语义应是：**编辑后的文本成为当前 BigBang 会话的新全文，普通模式中的选择、复制、分享、搜索和后续旋转都基于新全文。**

## 5. 原版实现结构

### 5.1 Activity 与页面编排

- `RealBoomActivity` 读取 `enter_edit_mode`、来源是否可编辑、特殊应用等启动信息。
- `BoomChipPage` 负责模式切换、动作回调、选区工具条、光标控制器、历史按钮和页面生命周期。
- `ActionBarPhoneTop`、`ActionBarPhoneBottom` 根据主模式 / 编辑模式切换按钮、可用状态和背景。

### 5.2 内容模型与排版

- `BoomContentView` / `BoomLinearLayout` 持有编辑状态、当前可编辑词块索引、选择集合、历史和增删改操作。
- 进入编辑态时，`performSecondBoomUpdate(...)` 对完整内容细分并重排。
- 退出编辑态时，用编辑后的 `allText` 重新分词并恢复普通词块布局。
- `ChipTextView`、`TextViewPlacer` 根据编辑态切换宽度、行高、背景和可编辑行为。
- 原版对 emoji、换行、空白、图片等类型有专门分支，说明编辑索引不能简单等同于 Java `char` 索引。

### 5.3 光标与键盘

- `CursorDragController` 管理大光标的点击、长按、拖动、连续删除、连续空格、符号、回车、语音和粘贴入口。
- `CursorDragViewExtend` 是大光标的组合 View。
- 一个专用输入控件接收软键盘文字，再通过监听器写回词块模型。

### 5.4 选区工具条

- `SelectToolbar` 复用同一选区背景与随动布局，根据是否处于编辑态切换按钮集合。
- 工具条可在选区滚出可视区域时切换到顶部或底部的 fake bar，保证操作仍可访问。
- `ActionStateUtils` 在动画、拖拽、语音和编辑转场期间阻止冲突动作。

## 6. Nova Text 当前差距

### 6.1 已经具备，可直接复用

- `BoomActivity` 已有 Compose 外壳、顶栏和底栏，并保留 legacy `BoomChipPage` 内容层。
- `BoomChipPage` 已有词块创建、选择状态保存、全选、选区恢复、相邻段落追加和二次分词。
- `BoomWordsLayout` 已有原文、词块字符范围、行列排版和按字符范围恢复选择。
- `BoomActionHandler` 已有选区背景、随动工具条、滚动吸附、复制、分享、搜索和词典动作。
- 当前旋转恢复已使用字符范围，适合作为编辑后重新排版时的稳定坐标基础。

### 6.2 当前缺失

- `BoomActivity.onEditMode` 仍调用 `showPlaceholder()`。
- Compose 顶栏 / 底栏只有普通模式，没有编辑态按钮状态机。
- 当前 `BoomWordsLayout` 主要按一次分词结果展示，没有可变全文、插入点和编辑单元模型。
- 当前 `BoomChipPage` 没有进入 / 退出编辑态、光标、键盘桥接和编辑历史。
- 当前 `BoomActionHandler` 的工具条只有二次分词、搜索、词典、分享、复制，没有删除、剪切、粘贴和取消按钮。
- 当前关闭逻辑只处理清除选择后退出，没有编辑脏状态确认。
- 相邻段落追加与编辑态的并发规则尚未定义。

### 6.3 不应采用的实现方式

- 不把整个内容区换成 Compose `TextField`，否则会丢失 BigBang 词块选择、选区工具条和现有动画。
- 不复制原版完整类树；只移植当前功能需要的模型和交互。
- 不在 Compose 和 legacy Java 中各维护一份可编辑文本。
- 不为编辑态单独新建第二套词块排版或第二套选择器。
- 不用吞异常、自动重置全文等兜底掩盖索引错乱；索引不一致应在调试日志和测试中直接暴露。
- 不承诺对第三方应用回写，也不为了模拟“保存”增加无障碍自动输入。

## 7. Nova Text 目标规格

### 7.1 首轮必须完成的核心能力

- 从现有顶栏“编辑”按钮进入编辑模式。
- 顶栏、内容区、底栏提供明确且一致的编辑态反馈。
- 可点击或拖动大光标改变插入位置。
- 可通过软键盘输入文本。
- 可插入空格、换行和粘贴文本。
- 可单次和长按连续删除。
- 可选中词块，并执行取消、删除、剪切、复制、粘贴。
- 可全选 / 取消全选。
- 可撤销和重做所有文本变更。
- 退出编辑态后，编辑后的全文重新分词并继续用于普通 BigBang 操作。
- 旋转后恢复模式、全文、插入点、选择和历史。
- 有未提交编辑时关闭页面，显示明确的舍弃确认。

### 7.2 后续增强，不阻塞首轮完成

- Smartisan 风格的符号面板。
- 大光标的语音输入和选区语音替换。
- 原版逐帧剪切 / 复制 / 删除动画。
- 图片、视频、语音等富媒体词块编辑。
- 外部 Intent 直接进入编辑模式。
- 对支持明确回写协议的自有来源增加“保存回来源”；未定义协议前不实现。

## 8. 建议实现设计

### 8.1 单一状态源

编辑全文、插入点、选择和历史必须由 legacy 内容层持有；Compose 只观察并显示页面模式、按钮可用状态和脏状态。

建议在 `BoomChipPage` 内持有一个最小编辑会话对象，职责仅包括：

- `originalText`：进入编辑模式时的会话全文；
- `text`：当前编辑全文；
- `cursorOffset`：基于全文的字符边界偏移；
- `selectedRanges`：当前选区对应的有序字符范围；
- `undoStack` / `redoStack`：编辑快照或可逆操作；
- `dirty`：当前文本是否不同于本次编辑入口文本。

不要把 UI View、Activity、剪贴板或分词器放入该对象。Compose 侧通过 `OnEditStateChanged` 一类回调接收只读 UI 状态。

### 8.2 编辑单元与索引

- 内部真值始终是完整字符串和字符边界，不把 View 下标当成永久文本索引。
- 中文单字、标点、空格和换行通常各为一个编辑单元。
- 拉丁字母可按原版视觉策略保持紧凑，但插入点仍必须落在合法字符边界。
- 使用 Unicode 字符边界切分，禁止拆开 emoji、代理对和组合字符。
- 所有选区、插入、删除和旋转恢复都先转换为字符范围，再重新生成临时词块 ID。
- 退出编辑态时，以编辑后的完整字符串调用当前 `CppJiebaTokenizer`，不能继续复用进入编辑前的 segment 数组。

### 8.3 历史模型

首轮采用有上限的文本快照历史即可，不引入命令框架：

- 每个用户可感知的编辑动作提交一个快照；
- 软键盘连续输入可按一次输入批次合并，避免每个 UTF-16 code unit 一个历史项；
- 连续删除在一次按下到抬起之间合并为一个历史项；
- 历史快照同时保存全文、光标和选区；
- 历史上限先定为 100，超过后丢弃最旧项；
- 新编辑清空 redo 栈。

### 8.4 Compose 与 legacy 的职责

`BoomActivity` / Compose 外壳负责：

- 普通态与编辑态顶栏 / 底栏切换；
- 进入、退出、全选、分享、撤销、重做、键盘按钮的事件转发；
- 系统返回和关闭时的确认对话框；
- 根据 legacy 回调刷新按钮 enabled 状态；
- 编辑态期间禁用 OCR 重跑、语言切换和“炸了又炸”入口。

`BoomChipPage` / legacy 内容层负责：

- 编辑态词块生成与排版；
- 插入点和大光标；
- 键盘输入；
- 选区到字符范围的转换；
- 所有文本变更和历史；
- 提交编辑文本后重新分词、刷新普通态词块。

`BoomActionHandler` 负责：

- 继续使用同一选区背景和随动工具条；
- 根据页面模式切换普通动作与编辑动作；
- 把删除、剪切、复制、粘贴转发给 `BoomChipPage`；
- 选择变化后更新光标和 Compose 按钮状态。

### 8.5 页面模式状态机

页面只允许以下稳定状态：

| 状态 | 内容 | 顶栏 / 底栏 | 允许动作 |
| --- | --- | --- | --- |
| `NORMAL` | 分词词块 | 现有普通工具 | 选择、搜索、词典、分享、OCR、相邻段落 |
| `ENTERING_EDIT` | 正在重排 | 编辑按钮禁用 | 不接受第二次进入或关闭外的内容动作 |
| `EDITING` | 编辑单元 + 大光标 | 编辑工具 | 输入、选择、剪切复制粘贴、撤销重做 |
| `EXITING_EDIT` | 正在重新分词 | 编辑按钮禁用 | 等待分词完成或报告真实错误 |
| `DISCARD_CONFIRM` | 保持当前画面 | 对话框 | 继续编辑或舍弃并关闭 |

不要增加“发生错误就自动恢复原文”的隐藏状态。重新分词失败时保留编辑文本和编辑态，让用户可以复制或重试，并记录明确错误。

目标：把现有多选体验扩展成可用编辑工具条。

- [x] 编辑态工具条切换为删除、取消、剪切、复制、粘贴。
- [x] 未选中时隐藏编辑选区工具条，不保留空白占位。
- [x] 删除 / 剪切后光标落到原选区起点。
- [x] 粘贴替换选区；复制后保留选区且不写入历史，已写入页面测试。
- [x] 全选按钮支持再次点击取消全选，并同步 enabled / contentDescription。
- [x] 工具条滚出屏幕时继续复用 fake bar 吸附逻辑。
- [x] 选区动作进入同一撤销 / 重做历史。

本阶段统一行为：复制完成后保留当前选区且不创建历史记录；删除、剪切和粘贴替换各作为一次可撤销的文本事务。

验收：选区操作与普通模式的搜索 / 分享工具条不串态；滚动、横屏和长文本下工具条不遮挡、不丢选择。

### 阶段 D：历史、关闭语义和会话集成

目标：让编辑模式达到真实场景可用标准。

- [x] 撤销 / 重做覆盖键盘输入、空格、回车、删除、剪切、粘贴和替换。
- [x] 按钮 enabled 状态严格由历史栈决定。
- [x] 退出编辑态后更新 `currentText` 和 `currentSegment`，普通态复制、分享、搜索全部读取新文本。
- [x] 编辑后退出再旋转，仍使用编辑后的文本，不从原 Intent 重新覆盖。
- [x] 编辑态触发系统返回、关闭图标或外层 dismiss 时，按 dirty 状态显示舍弃确认。
- [x] 相邻段落只能在普通态追加；进入编辑态后冻结当前会话边界。
- [x] `onNewIntent` 到来时若当前编辑 dirty，先按明确策略确认舍弃，不能静默覆盖。
- [x] 增加 TalkBack 描述、键盘导航和硬件快捷键：全选、复制、剪切、粘贴、撤销、重做。

本阶段统一语义：左上角“退出编辑”提交当前文本；系统返回、关闭、外层 dismiss 和新 Intent 在文本 dirty 时先显示“继续编辑 / 舍弃”确认。确认舍弃才关闭当前页或接受新文本；取消则保留文本、光标、选区和历史。硬件键盘支持 Ctrl/Cmd+A、C、X、V、Z、Shift+Z 和 Y。

验收：完成第 11 节全部核心用例后，才可从 README 和开发计划移除“编辑模式未支持”。

### 11.2 页面与交互用例

1. 从预制文本调试入口打开 BigBang，点击编辑，进入编辑态。
2. 不做修改退出编辑，文本和普通分词结果不变。
3. 在首字前、两词之间、末字后分别插入文字。
4. 插入空格和换行，确认词块即时换行且光标位置正确。
5. 单击删除和长按删除，确认不跳字、不越界。
6. 选择单个、多行和全量词块，分别执行复制、剪切、删除、粘贴替换；确认复制后选区仍保留且不会创建历史记录。
7. 连续撤销到初始文本，再全部重做。
8. 编辑后退出，确认搜索、复制、分享使用新文本。
9. 编辑未提交时关闭，分别测试“继续编辑”和“舍弃”。
10. 编辑中旋转横竖屏，确认文本、光标、选区、历史和工具条位置。
11. 编辑中按系统返回、点击外部遮罩、收到新 Intent，确认不会静默丢内容。
12. 编辑长文本并滚动，确认大光标和选区工具条吸附正确。
13. 测试深色模式、字体放大、横屏、平板 / 分屏和 Android 7 最低支持版本。
14. 使用 TalkBack 检查编辑按钮、光标动作、选区动作和撤销 / 重做描述。
15. 使用硬件键盘确认 Tab 焦点可达各操作，并验证 Ctrl/Cmd+A、C、X、V、Z、Shift+Z、Y。

## 12. 完成标准

编辑模式只有同时满足以下条件才算完成：

- 不再显示“功能建设中”；
- 进入、退出和关闭是三个语义明确的操作；
- 用户可以在真实文本中插入、删除、换行、剪切、复制、粘贴；
- 大光标、软键盘和多选工具条都可独立完成编辑；
- 撤销 / 重做和未保存确认可靠；
- 编辑后的文本真正进入当前 BigBang 会话，而不是只改变画面；
- 旋转、长文本、emoji、横屏和最低支持版本没有数据损坏；
- 普通模式现有的选择、搜索、分享、OCR 和相邻段落行为没有回归；
- `bash ./gradlew assembleDebug` 通过。

首轮完成后再更新 README、总体开发计划和 CHANGELOG，并按小功能版本规则递增 Z 版本号。本文本身属于代码无关文档更新，不递增版本号。

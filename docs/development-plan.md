# Nova Text 开发计划

## 当前状态

项目已经从"迁移脚手架阶段"进入"补能力、补 feature、补兼容性"阶段。

当前已稳定接通的主链路：

- 本地 `cppjieba` 分词与后台预热
- Compose 设置页、搜索页、大爆炸外层浮层壳
- 悬浮球 + 静默截图缓存 + 无障碍文本提取 -> BigBang
- 图片调试 / 图片分享 -> OCR 范围选择 -> BigBang
- 悬浮球白名单 OCR -> 截图 -> 全屏 OCR -> 最近文本块 -> BigBang
- BigBang 内重进 OCR、临时切换 OCR 语言
- "炸了又炸"相邻段落追加
- 悬浮球启动 loop 动画、BigBang 入场动画和关闭动画
- Android 7-10 MediaProjection 截图，支持 Shizuku 开关切换
- Android 7-9 安装支持（未做实机完整测试）
- 二次分词（"菜刀"功能）已接入
- 自定义搜索源已支持 URL、图标和名称配置
- 已接入悬浮球 / 截图 OCR 快捷设置 Tile、应用快捷方式和 Android 通用文本分享
- 已接入 Android 13+ 通知权限状态与启动向导授权入口
- 已增加悬浮球锁定左右侧和 BigBang 行距设置

## 目标四：后台保活与系统功能增强

### 背景

悬浮球和后台服务的稳定性直接决定了核心体验的可用性。当前已接入前台服务和后台弹出页面权限引导，后续重点转向不同 ROM 与长时间运行场景的验证。

### 详细需求

- [x] **Android 后台前台服务与保活链路**
  - 高版本 Android（>= Android 14）启用前台服务（Foreground Service）以降低被杀概率
  - 带合理的通知渠道和通知文案，避免被用户直接关掉
  - 兼容低版本 Android（< 12）的后台策略，不做一刀切
  - 保活状态与悬浮球开关联动，悬浮球关闭时自动停止保活

- [x] **小米系统后台弹出页面权限申请 / 提醒**
  - 检测当前系统是否为 MIUI
  - 检测"后台弹出页面"权限是否已授予
  - 若未授权，引导用户跳转至权限设置页，并给出图文提示
  - 可选：在启动时 / 首次使用悬浮球时触发检测
  - 同理可扩展至其他国产 ROM（ColorOS、OriginOS 等）

### 验收

- [x] 前台服务启动、通知和悬浮球开关联动已接通
- [x] 小米设备后台弹出页面权限引导流程已接通

## 当前不作为主目标

这些事不是永远不做，只是不是下一阶段主目标：

- 全量 Kotlin 化 legacy Java 内核
- 全量 Compose 重写 BigBang 词块布局
- 大规模目录重排
- 引入新的复杂架构层

原因很简单：这些成本高，但不直接补当前最缺的用户能力。

## 执行原则

1. 继续保持"先让主链路可用，再补抽象"。
2. 文档只写当前真实状态，不把目标态写成已完成。
3. 新链路优先复用现有 launcher / dispatcher / settings，不再各起一套分支。
4. 继续保留 legacy Java BigBang 内核，除非有明确收益，否则不重写。
5. 悬浮球主链路的截图、loop 动画和 BigBang 启动门槛继续收口在共享链路里，不再拆分成各入口私有时序。

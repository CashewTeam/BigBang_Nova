# Nova Text 开发计划

## 当前状态

项目已经从“迁移脚手架阶段”进入“补能力、补 feature、补兼容性”阶段。

当前已稳定接通的主链路：

- 本地 `cppjieba` 分词与后台预热
- Compose 设置页、搜索页、大爆炸外层浮层壳
- 悬浮球 + 静默截图缓存 + 无障碍文本提取 -> BigBang
- 图片调试 / 图片分享 -> OCR 范围选择 -> BigBang
- 悬浮球白名单 OCR -> 截图 -> 全屏 OCR -> 最近文本块 -> BigBang
- BigBang 内重进 OCR、临时切换 OCR 语言
- “炸了又炸”相邻段落追加
- 悬浮球启动 loop 动画、BigBang 入场动画和关闭动画
- Android 7-10 Shizuku 截图回退

当前仍明显未完成的部分：

- 编辑模式仍未落地，当前仍是占位入口
- 横屏与平板适配尚未系统完成
- 多机型、多 Android 版本的实机兼容性验证和 Debug 仍未收口

## 目标一：补齐 BigBang 交互 feature

### 已完成

- “炸了又炸”已接通
- BigBang 内已支持重新 OCR
- OCR 链路已支持临时语言切换重跑
- 搜索页搜索源和浏览器操作栏已补一轮能力
- legacy 内层已补二次分词入口

### 下一步

- [ ] 实现真正可用的编辑模式
  - 不是 placeholder
  - 有明确进入、退出和状态反馈
  - 与现有选词、多选、分享行为不冲突
- [ ] 继续补 BigBang 操作细节
  - 顶部 / 底部操作栏交互一致性
  - 空白区点击与拖拽反馈
  - “炸了又炸”文案和阻尼体验
  - 二次分词后的范围框与随动按钮刷新稳定性

### 验收

- [ ] 编辑模式可在真实场景下使用
- [ ] BigBang 主交互不再依赖 placeholder
- [ ] 现有 OCR / 搜索 / 分享能力不因 feature 补齐而回归

## 目标二：横屏与平板适配

### 下一步

- [ ] 收口横屏下的悬浮球、BigBang、搜索页和 OCR 范围选择页布局
- [ ] 收口平板和大屏设备的浮层尺寸、安全区和交互边界
- [ ] 清理横竖屏切换后的返回栈、浮层尺寸和触点坐标偏差问题

### 验收

- [ ] 横屏下悬浮球、BigBang、搜索页不会出现明显越界和错位
- [ ] OCR 范围选择页在横图和大屏设备上可稳定操作
- [ ] 平板和多窗口场景下浮层没有明显嵌套感或留白错误

## 目标三：多机型与多 Android 版本适配验证

### 下一步

- [ ] 继续排查常见三方 App 的无障碍命中率和 OCR 命中率
- [ ] 按机型和 Android 版本建立最小兼容性问题清单
- [ ] 继续收敛截图路径、前台包名识别、动画时序和页面性能
- [ ] 建立最小问题清单
  - 问题 App
  - 问题机型 / Android 版本
  - 复现步骤
  - 当前行为
  - 期望行为

### 验收

- [ ] 主流机型上的悬浮球体验基本稳定
- [ ] 设置页 / BigBang / 搜索页在目标设备上无明显掉帧和严重视觉错误
- [ ] 无障碍与 OCR 分流、返回栈、浮层关闭和 OCR 跳转逻辑在不同 Android 版本下可预测

## 当前不作为主目标

这些事不是永远不做，只是不是下一阶段主目标：

- 全量 Kotlin 化 legacy Java 内核
- 全量 Compose 重写 BigBang 词块布局
- 大规模目录重排
- 引入新的复杂架构层

原因很简单：这些成本高，但不直接补当前最缺的用户能力。

## 执行原则

1. 继续保持“先让主链路可用，再补抽象”。
2. 文档只写当前真实状态，不把目标态写成已完成。
3. 新链路优先复用现有 launcher / dispatcher / settings，不再各起一套分支。
4. 继续保留 legacy Java BigBang 内核，除非有明确收益，否则不重写。
5. 悬浮球主链路的截图、loop 动画和 BigBang 启动门槛继续收口在共享链路里，不再拆分成各入口私有时序。
